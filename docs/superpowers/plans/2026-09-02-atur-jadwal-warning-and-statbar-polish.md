# AturJadwal Warning Frame & BGStat Bar Polish — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reframe the AturJadwal "PERINGATAN" dialog onto the finished
`penjadwalan_card_bg.png` art, and give the five BGStat progress bars a
lively, finished capsule look (inset track, legible value label, fill and
pop animation) without moving the bars or their final icons.

**Architecture:** Three layers, in the order the project's design system
demands. (1) The warning dialog's frame becomes a `NinePatchRect` in
`atur_jadwal.tscn` so the square 1080×1080 card art fills a 740×428 frame
without smearing its painted corners. (2) The shared bar look is a Theme
change in `ThemeFactory._build_progress` plus a rebake — no
`theme_override_*`, and no new `DesignTokens` `@export` (a new export is
invisible to a running editor and would force a restart). (3) The
liveliness is behaviour in `Scripts/UI/StatBar.gd`, which also picks up a
real bug on the way: it builds a *second* `ValueLabel` on top of the one
already authored in the scene.

**Tech Stack:** Godot 4.6, GDScript, the project Theme
(`Assets/Theme/kejartes_theme.tres`, baked from `design_tokens.tres`),
`Scripts/Design/Juice.gd`, McpTestSuite tests run via the godot-ai MCP
`test_run`.

**Spec:** No separate spec doc. The requirements are the user's request,
captured verbatim in *Context* below; the mockup of record for this screen
is `docs/superpowers/specs/2026-09-01-art-pass-and-screen-restyle.md` and
`docs/superpowers/plans/2026-09-01-atur-jadwal-mockup.md`.

## Global Constraints

- **Godot 4.6**, portrait 1080×1920 design space.
- **Never add a `theme_override_*`.** Use a `ThemeFactory` type variation.
  Only layout-only constant overrides (`separation`, `margin_*`) are allowed.
- **No new `@export` on `DesignTokens`.** A new export on a `Resource`
  `class_name` is invisible to the running editor and needs a restart —
  this is exactly the trap that left the shelf deferred in
  `2026-09-01-atur-jadwal-mockup.md`. Reuse existing tokens only:
  `surface_sunken`, `outline_card`, `outline_width`, `shadow_color`,
  `shadow_size`, `shadow_offset`, `radius_pill`, `space_xs`, `dur_fast`,
  `dur_normal`, `font_caption`.
- **No visual built at runtime.** Static chrome is a node in the `.tscn`.
  `tests/test_viewport_editability.gd` ratchets this — never raise its
  `BASELINE`.
- **Never hand-edit `atur_jadwal.tscn` while the editor is attached.** Go
  through the MCP: `scene_open` → `node_create` / `node_set_property` /
  `node_manage` / `batch_execute` → `scene_save`. `anchors_preset` is
  inert (set the four anchors); numbers unquoted; `node_create` appends
  last, so z-order needs `move_node`; a node's *type* can only be changed
  by delete-and-recreate.
- **Rescan after editing any `.gd`, before `test_run`:**
  `filesystem_manage(op="scan")`. Otherwise the runner serves a stale autoload.
- **After any `ThemeFactory.gd` edit the theme must be rebaked** by running
  `Scripts/Design/BakeTheme.gd` in the editor via File > Run
  (Ctrl+Shift+X). There is no headless path.
- **The godot-ai MCP bridge is single-client.** Subagents write code; the
  session holding the editor runs `scene_open` / `test_run` / screenshots.
- Every script needs a `##` file header and a `##` line on every `@export`
  (`tests/test_script_documentation.gd` is a hard gate).
- Game-facing text stays **Indonesian**; systems code is English.
- Commits: Conventional Commits with a scope, e.g. `fix(atur-jadwal): ...`.

### Task 1: Peringatan wears the finished card art

The dialog currently draws `Assets/Images/UI/pngwing.com (2).png` — a
746×986 stock placeholder — in a 740×428 `TextureRect` with
`expand_mode = 1` (IGNORE_SIZE) and the default *stretch* mode. The
replacement `penjadwalan_card_bg.png` is **1080×1080 square**; scaling a
square into a 1.73:1 frame would squash its painted corners and border. A
`NinePatchRect` keeps the corners at native size and stretches only the
middle, which is what the same art already does structurally in the
`Penjadwalan` panel (which happens to be near-square there, so it got away
with a `TextureRect`).

`penjadwalan_card_bg.png` is already loaded in the scene as
`ExtResource("9_cardbg")` — no new `ext_resource` is needed, and
`3_a6kja` becomes unreferenced (leave the ext_resource line; the editor
prunes it on save).

- Test: `tests/test_atur_jadwal.gd`

**Interfaces:**
- Consumes: nothing from other tasks.
- Produces: the node path `Peringatan/TextureRect` is **unchanged** — the

### Task 2: StatBar stops building a second value label

`StatBar._sync_label()` creates a `Label` named `ValueLabel` whenever
`show_value_label` is on and its own `_label` is null. All five bars in
`atur_jadwal.tscn` **already have** an authored `ValueLabel` child, so at
runtime each bar renders two overlapping labels — Godot renames the new one
and only the script-built one ever counts up. The authored one sits there
frozen at "0%". This is the single biggest reason the bars read as
unfinished, and it must be fixed before any styling work, or the styling
lands on the wrong label.

The fix: adopt an existing child before building one. Also give the label
the `BarLabel` variation instead of `CaptionLabel` — `BarLabel` exists
precisely for text sitting on top of a bar whose backdrop may be either the
pale track or a saturated fill (white glyph, dark rim); `CaptionLabel`
assumes a known backdrop and disappears against the fill.

**Files:**
- Modify: `Scripts/UI/StatBar.gd`
- Modify: `Scenes/AturJadwal/atur_jadwal.tscn` (five `ValueLabel` nodes)
- Test: `tests/test_atur_jadwal.gd`

**Interfaces:**
- Consumes: nothing from Task 1.
- Produces: `StatBar` guarantees exactly one child `Label` named
  `ValueLabel`, and `StatBar.set_stat(new_value: float, animate: bool = true)`
  drives *that* label. Task 4 relies on this.

- [ ] **Step 3: Make StatBar adopt the authored label**

In `Scripts/UI/StatBar.gd`, replace `_sync_label()` with:

```gdscript
func _sync_label() -> void:
	if not is_inside_tree():
		return
	if _label == null:
		# The scene may already author a ValueLabel (every AturJadwal bar
		# does). Adopt it -- building a second one leaves the authored
		# label frozen at its design-time text underneath the live one.
		_label = get_node_or_null("ValueLabel") as Label
	if show_value_label and _label == null:
		_label = Label.new()
		_label.name = "ValueLabel"
		_label.set_anchors_preset(Control.PRESET_FULL_RECT)
		add_child(_label)
	if _label == null:
		return
	_label.visible = show_value_label
	_label.theme_type_variation = &"BarLabel"
	_label.horizontal_alignment = HORIZONTAL_ALIGNMENT_CENTER
	_label.vertical_alignment = VERTICAL_ALIGNMENT_CENTER
	_label.mouse_filter = Control.MOUSE_FILTER_IGNORE
	_label.text = value_format % int(round(value))
```

Note what changed beyond adoption: an unwanted label is now *hidden* rather
than `queue_free`d, because an authored node must survive a property
toggle; and the styling is applied to whichever label we ended up with,
adopted or built. Everything else in the file stays as-is.

### Task 3: The StatBar track becomes a finished capsule

Today `_build_progress` gives the track a flat `surface_sunken` fill at
`radius_pill` and nothing else, and the fill has no inset — the coloured
fill runs flush to the track's outer edge, which is what makes the bars
read as a debug widget rather than art. The rest of this project's chrome
is "sticker" styled: white rim plus a soft drop shadow. Bring the track in
line, and inset the fill so the capsule shows a visible rail on all four
sides.

`DesignTokens` export** (see Global Constraints).

### Task 4: The bars come alive

Two motions, both cheap and both already expressible with `Juice`:

1. **On change** — a bar whose value moves gives a short squash-pop, so a
   schedule edit visibly lands. Opt-in via an `@export` so SemesterEnd's
   end-of-week readout and ReportCard's static display are unaffected.
2. **On student switch** — the five rows stagger in, left icon and bar
   together, instead of all snapping at once. This is the "cute,
   comfortable for the eye" part of the request, and it costs one call at
   the end of `_update_student_display`.

The icons stay exactly where they are — they are final art. The stagger
only fades and lifts them; their `offset_*` values (which
`test_each_row_carries_its_mockup_icon` asserts are centred on their bars)
never change.

- Produces: `StatBar` gains `@export var pop_on_change: bool = false`.
