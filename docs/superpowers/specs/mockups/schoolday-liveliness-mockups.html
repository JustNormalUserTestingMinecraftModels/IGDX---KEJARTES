KejarTes — SchoolDay & Daily Results mockups

Reference mockups for the SchoolDay liveliness pass and the Daily Results reward layer. Every element here maps to a decision recorded in the design specs. These are indicative visuals for the team to build against, not final art — real assets are drop-in-replaceable SVG textures, and all faces/crowns/stars ship as textures (no emoji), per the project's rules.

Design date 2026-09-24 · pairs with docs/superpowers/specs/2026-09-24-schoolday-liveliness-design.md

Behavioral source of truth: schoolday-interactive-prototype.html (same folder) runs the full loop with final motion. Where a still frame here differs, the prototype wins — notably the day-screen roster is now a scrolling avatar strip (energy/mood rings), not the full-width rows some frames below still show.

3 · Daily Results — the reward layer

Built on data the popup already computes. Verdict header (teacher face + reactive headline + 1–4 stars), reward tally strip, "Bintang Hari Ini" crown, and per-student cards with reaction faces. Star rule: targets-crossed drives the tier, net gain/loss is the tiebreak, floor at 1★. Weekly-goal meter intentionally excluded.

Verdict ladder (star rule)

  • 1★ · Hari yang berat — net losses, no target crossed. "Besok lebih baik!"
  • 2★ · Lumayan — net positive, no target crossed today.
  • 3★ · Hari produktif! — at least one target crossed.
  • 4★ · Luar biasa! — multiple targets crossed, nobody went down.

Build notes

  • Escalating confetti: small daily, fireworks on the week's final day.
  • All icons/faces/crown ship as SVG textures — no emoji.

Tile depth — options & build notes

  • A · Depth (recommended) — vertical gradient fill + chunky drop shadow + 1px top highlight + tinted icon discs. Reads raised without new art beyond a gradient.
  • B · Trophy strip — a colored cap strip per tile (strongest category coding).
  • C · Minimal bevel — keep flat white but add bevel + a tinted number + reveal sparkle. Smallest change.
  • Godot note: drop shadow + bevel are free on StyleBoxFlat (shadow_size/offset + border) via a ThemeFactory variation — no theme_override. The gradient specifically needs a small gradient texture (StyleBoxTexture 9-slice) or a GradientTexture2D behind; the team decides flat-with-shadow vs gradient-texture.
  • Decision: the implementing Claude confirms A / B / C (or flat+shadow only) with the user before building.
